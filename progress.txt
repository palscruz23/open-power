- Keep this section updated with reusable patterns discovered during implementation.
- Short-circuit edge contribution labels should be laid out from the connected bus outward and stacked by a stable per-bus edge-angle order in `frontend/src/pages/LoadFlowStudyPage.jsx` so repeated runs do not overlap the bus-side fault metrics.
- Protection-ready palette shortcuts should serialize as an existing asset node type plus prefilled `data.protection` defaults so the fixed node taxonomy and backend `asset_type` validation stay aligned.
- Backend study verification should reuse the shared representative payload builders in `backend/test_study_samples.py` so load-flow, ANSI, IEC 60909, and protection tests stay aligned on the same sample-network assumptions.
- Arc-flash regression coverage should keep focused request-model edge cases in `backend/test_arc_flash.py` and mirror one successful sample plus one invalid-assumption case in `backend/test_study_verification.py` so the shared study suite exercises the maintained fixtures too.
- Shared load-flow and short-circuit diagrams persist through `getStorageKey()` and `sanitizeGraphForPersistence()` in `frontend/src/pages/LoadFlowStudyPage.jsx`; keep study-specific controls in component state and out of the saved graph payload.
- UI-only study tabs should keep draft inputs and readiness/run state in local React state rather than extending `buildNetworkModel()` or persisting extra study data into the shared graph.
- Frontend-only placeholder studies should add their tab/route in `frontend/src/App.jsx`, keep draft inputs in `LoadFlowStudyPage.jsx`, and render prerequisites plus disabled outputs from `frontend/src/components/ControlPanel.jsx` until backend support exists.
- Run backend verification with the repo-local Windows virtualenv (`.venv\Scripts\python.exe`); the system Python in this workspace may not have `pandapower` installed.
- Representative backend study coverage should reuse the shared sample payload builders in `backend/test_study_samples.py` so load-flow, ANSI short-circuit, IEC 60909 short-circuit, and protection coordination stay aligned on the same maintained fixtures.
- Shared frontend network serialization now lives in `frontend/src/utils/networkPayload.js`; add base graph fields in `buildNetworkModel()` and layer study-specific request options through the dedicated payload builders instead of copying mapping logic into each study flow.
- Arc-flash study assumptions should stay ephemeral in `LoadFlowStudyPage.jsx` / `ControlPanel.jsx`, then serialize through `buildArcFlashPayload()` into the backend `ArcFlashInput` model instead of being persisted on the shared graph.
- Arc-flash frontend results should follow the same transient discipline as short-circuit: keep overlays on node `data`, clear them in `LoadFlowStudyPage.jsx` before switching studies, and strip the keys through `TRANSIENT_NODE_DATA_KEYS` so saved diagrams stay clean.
- Arc-flash canvas overlays should annotate the selected study bus and its directly connected equipment nodes from `LoadFlowStudyPage.jsx`; keep that targeting helper aligned with `SymbolNodes.jsx` instead of persisting a separate equipment selection.
- Short-circuit result payloads should keep the frontend's generic `current_ka` fields stable while exposing method-aware `result_key`/`result_label` metadata and standard-specific branch keys for ANSI vs IEC outputs.
- Short-circuit frontend updates need coordinated changes in `LoadFlowStudyPage.jsx` result resets, `SymbolNodes.jsx` fault badges, and `ControlPanel.jsx` result rendering so new fault metadata stays transient and the panel does not fall back to raw JSON.
- Protection-device modeling is persisted on eligible node `data.protection` objects in the editor, then flattened into the shared API payload as `protection_devices`; keep those two shapes aligned whenever protection settings change.
- Protection coordination now returns per-device summaries plus a top-level `curves` array; future charting and analysis work should extend that response instead of inventing a second protection-results shape.
- Transformer protection curves currently choose the protected transformer side by comparing the configured pickup current against the transformer's rated HV/LV currents; keep that heuristic aligned with any future transformer-side settings.
- Protection coordination charting lives in `frontend/src/components/ControlPanel.jsx` as a native SVG view driven directly by the backend `curves` array; keep loading/error/content state there and avoid adding a second frontend-only curve model.
- Protection coordination feedback should extend the backend `analysis` block (`warning_count`, `warnings`, `scope_notes`) so warnings and out-of-scope notes stay separate from chart data and device summaries.
- Advanced-study validation should be duplicated intentionally: `LoadFlowStudyPage.jsx` should preflight disconnected protection assets and unsupported study modes for fast UI feedback, while `backend/main.py` must enforce the same rules with explicit HTTP 400 messages.
- Arc-flash backend results should reuse the existing short-circuit and protection helpers for available fault current and device clearing time, then expose study outputs through `summary`, `assumptions`, `calculation`, and `limitations` blocks so the frontend can extend rendering without a second payload shape.
- Arc-flash safety review labels should be emitted from a dedicated backend `guidance` block; keep frontend PPE/severity rendering and transient canvas labels tied to that block instead of inferring guidance from raw numeric summary fields.
- ANSI short-circuit outputs are currently derived from the pandapower IEC 60909 max-case engine by applying a nominal-voltage conversion; keep the limitation messaging and `voltage_factor_mode` / `current_scale` metadata aligned whenever that path changes so ANSI does not silently alias IEC duties.
